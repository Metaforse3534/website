SECURITY

Security & Responsible Disclosure

Verified security information for Orbit accounts, the public website, the authenticated workspace, AI requests, connected tools, billing, and vulnerability reports.

Updated: August 23, 2026Orbit LabsNo compliance certification claimed
The website repository verifies HTTPS deployment headers, protected billing redirection, and documented account controls. It does not prove a specific cipher, encryption-at-rest algorithm, execution-enclave architecture, audit certification, backup schedule, monitoring provider, or completed DPA. Those claims have been removed pending evidence.

001 / Account controls

The current product documentation describes password-based authentication, email verification, password reset, protected workspace routes, and optional six-digit TOTP two-factor authentication. Users should protect passwords and recovery methods and report suspected access promptly.

002 / Transport and browser protections

Orbit is served over HTTPS in production. The Vercel configuration adds content-type sniffing protection, same-origin framing, and a strict-origin referrer policy. The exact production TLS version and full header set are controlled by the hosting deployment and should be independently verified after release.

003 / Data access and isolation

Orbit limits data access through authenticated product routes and account ownership checks described by the app documentation. The public repository does not contain the production database policies or infrastructure configuration, so no unverified tenant-isolation, RLS, encryption-at-rest, backup, or key-management claim is made here.

004 / AI and tool safety

Model requests and tool actions can expose content to selected providers or connected services. Users should grant the least access needed, keep secrets out of prompts, and review consequential browser, desktop, code, messaging, and automation actions before completion.

005 / Payment handling

The website disables its legacy payment-intent endpoint and redirects purchases to Orbit Billing, where the documented Stripe flow handles card collection. Never send full card numbers, passwords, private keys, or authentication codes through support forms or email.

006 / Data deletion and incidents

Users may contact support about account or data deletion. The production deletion timing, backup expiry, incident-response workflow, and notification contacts require confirmation before stronger public commitments can be made: [DATA RETENTION PERIOD REQUIRED] [INCIDENT RESPONSE PROCESS REQUIRED].

007 / Responsible disclosure

Send suspected vulnerabilities to security@orbitdev.org. Include the affected URL or version, impact, reproducible steps, and a safe proof of concept. Do not access other users’ data, disrupt service, use social engineering, demand payment, or publish details before Orbit has had reasonable time to investigate.

008 / Scope and safe harbor

Only test systems you are authorized to test. A formal vulnerability scope, response target, disclosure timeline, and safe-harbor promise have not been approved: [VULNERABILITY DISCLOSURE TERMS REQUIRED]. Orbit will review good-faith reports and may ask for additional details.

009 / Certifications

Orbit does not currently claim SOC 2, ISO 27001, HIPAA, PCI DSS certification, or another independent security certification on this page. Payment-provider compliance does not automatically certify Orbit as a whole.
